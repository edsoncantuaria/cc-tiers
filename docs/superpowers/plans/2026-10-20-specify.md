# cc-tiers 0.6 — specify and ask: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The orchestrator turns a short request into acceptance criteria (after research), asks only questions that change the result, and every writer and reviewer works against those criteria; the benchmark gains a short-prompt variant that measures this.

**Architecture:** Mirror the research gate: a `CC_TIERS_SPEC_BEGIN/END` block (or `CC_TIERS_SPEC: none - <reason>`) required by `checkDelegation` for implementer/architect, stripped from routing signals and header parsing like the research block. The specify/ask step lives in the session agents' prompts (only the main session can call `AskUserQuestion`). The runner disables `AskUserQuestion` for every config.

**Tech Stack:** Node 18+ ESM, `node:test`, no dependencies; Claude Code plugin 2.1.295+.

**Spec:** `docs/superpowers/specs/2026-10-20-specify-design.md` (extends `2026-10-19-quality-first-design.md`)

## Global Constraints

- Delimiters `CC_TIERS_SPEC_BEGIN` / `CC_TIERS_SPEC_END` on their own lines; escape line `CC_TIERS_SPEC: none - <reason>`; block headings `Criteria:`, `Edge cases:`, `Assumed:`; origin tags `(request)`, `(repo: file:line)`, `(docs: <link or path>)`, `(decided: <why>)`, `(user)`; block ≤ ~15 lines.
- Refusal text, verbatim: `cc-tiers: write the acceptance criteria for <task> between CC_TIERS_SPEC_BEGIN and CC_TIERS_SPEC_END before delegating it, or add CC_TIERS_SPEC: none - <reason>.`
- Option `specify` (`on`/`off`, default `on`), `"specify": true` in routing defaults, project key `specify`, `/config` wins; session line starts `Specify: on` / `Specify: off`.
- Questions: once, before implementing, all together, at most 3, `AskUserQuestion` multiple choice with the recommended option first and its reason; only when two reasonable readings lead to different code and neither the project nor the version's docs decide. If the tool is unavailable or denied: proceed with the recommended option, record it under `Assumed:`, say so in the final report; never wait.
- Gate runs before any state change; worker exempt; `specify: off` → no gate.
- Plugin text in English; README EN/pt-BR line-for-line in sync; CHANGELOG 0.6.0 bullets; version stays 0.6.0.
- Commits: Portuguese subject, blank line, `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push only at the end (branch `qualidade-primeiro`).

## Review Focus

1. A pasted spec block that contains `CC_TIERS_*` lines (e.g. a pasted researcher trailer inside it) must not override the writer's headers → Task 1 test.
2. A spec block with only headings (`Criteria:` and nothing else) must be refused → Task 1 test.
3. A prompt carrying both the research block and the spec block: both stripped from routing/effort signals → Task 1 test.
4. The short check must not require anything the short prompt or the fixture's own files do not show → Task 3 test (reference passes both checks; naive fails both).
5. `AskUserQuestion` disabled for every config in the runner, including `opus`/`sonnet` → Task 3 test on the args builder.
